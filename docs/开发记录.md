# Miku 数织自动闯关（Hatsune Miku Logic Paint S）

给 Steam 版游戏做的数织（nonogram）自动闯关机器人：截屏读题 → OCR 识别提示数字 →
内置求解器解算 → 原生鼠标点击落子 → 自动过关进下一关。带一个网页版控制面板，
打包成双击即开的 `MikuPanel.exe`。

**唯一入口：双击 `启动面板.bat`**（会先自检、需要时自动重新打包，再开面板）。
纯命令行跑机器人仍然是 `启动.bat`（或 `启动.bat 校准`）。

---

## 一、什么才是"真源"

整个目录里只有这 **三份**东西是真正要改的，其余都是产物或现场：

| 真源 | 作用 | 硬约束 |
|---|---|---|
| `miku_logic_paint_bot.py` | 主脚本（识别/求解/点击/循环，全部逻辑） | **必须留在根目录**：面板按"exe 同级目录"找它 |
| `miku_bot_config.json` | 唯一配置（窗口关键字、点击节奏、棋盘几何…） | 面板读的固定就是这份路径 |
| `panel/index.html` | 面板界面（暗色控制台） | 只能通过重新打包进 exe 生效 |

`MikuPanel.exe` 里**内嵌了这三份的副本**，作用是"独立运行时的兜底"。
正常运行时面板加载的是上面三份真源，所以：

> **改源码 → 跑一次打包 → 面板才会带上你的改动。**
> 忘了打包不会"跑错代码"，但会让 exe 的兜底副本变旧；`启动面板.bat` 每次都会自检并自动补上
> （2026-09-29 00:56 真实触发过一次，`build/versions/` 里有那次的备份）。

配置里原来还有一个 `stars` 字段（关卡方块指纹 → 已拿到的星数），用来支撑「自动重打未满三星的
关卡」；**2026-09-29 深夜那套模块整体删除了**（见第九节），这份配置里已经没有它，
再手动加回去也不会被读。

## 二、日常只有这几条命令

```bat
启动面板.bat                       :: 自检 +（必要时）自动打包 + 开面板
python tools\panel_build.py        :: 只打包：把三份真源同步进 exe，并自证没写坏
python tools\panel_verify.py       :: 只体检：内容物比对 / 副本巡检 / 运行环境
python miku_logic_paint_bot.py --selftest   :: 不用游戏的自检（求解器 + 定位 + 列表布局 + 合成画面端到端）
python debug\probe_special_list.py          :: 特别谜题选关界面识别（实拍图 + 合成用例 + 回归，见第十二节）
python debug\probe_special_list.py --live   :: 真机只读看一眼：布局判定 + 25 格逐格判定 + 会点哪一格
```

打包过程是**原地追加 + 重写目录**（不动 PE 段、不动任何依赖库）：只有内容变了的条目才会被写，
写完先落成 `MikuPanel.exe.new` 并做**全量体检**（253 个条目全部可读、未改条目字节级一致、
目标条目与真源一致），体检通过才备份旧版并原子替换。任何一步失败 → 原 exe 一个字节都不动。

## 四、环境要求

- **Python 3**（装了才能跑主脚本、打包、校验）
- **Tesseract-OCR**（读提示数字；装在 `C:\Program Files\Tesseract-OCR\` 或加入 PATH）
- **WebView2 运行时**（面板窗口用；Win11 自带）
- 游戏窗口标题含 `Logic Paint` / `Hatsune` / `Miku`（可用 `--window` 指定）

紧急停止：**F8** / **Esc** / 把鼠标甩到屏幕左上角。

## 五、改 `.bat` 时注意编码（踩过坑）

`启动.bat` 和 `启动面板.bat` 都必须是 **GBK（代码页 936）** 编码：cmd.exe 是按 GBK 读 `.bat` 的，
存成 UTF-8 会让中文变乱码，严重时字节错位还会让 cmd 把后面的行解析错（报一堆莫名其妙的语法错误）。
另外本机 Python 默认以 UTF-8 输出（环境变量 `PYTHONUTF8=1`），直接打到 936 控制台也是乱码，
所以 `启动面板.bat` 里先把 `PYTHONUTF8=0` / `PYTHONIOENCODING=gbk` 钉死。

改完内容后按这样转回 GBK（PowerShell）：

```powershell
$gbk = [System.Text.Encoding]::GetEncoding(936)
$p   = '<工程目录>\启动面板.bat'
$t   = [System.Text.Encoding]::UTF8.GetString([IO.File]::ReadAllBytes($p)).TrimStart([char]0xFEFF)
[IO.File]::WriteAllBytes($p, $gbk.GetBytes(($t -replace "`r`n","`n") -split "`n" -join "`r`n"))
```

## 十二、2026-10-01：特别谜题（拼图）选关模式

「特别谜题」是另一种关卡类型（一轮 8 页、每页一整幅图切成 25 块，每块一道数织题），
**外面那一圈界面跟普通谜题完全不是一套**，所以单独加了一套「切换下一关」的走法。

实测（1920×1080 客户区，两份实拍截图一致）：

| 元素 | 普通谜题 | 特别谜题 |
|---|---|---|
| 选关区 | 中间一块浅黄卡片 5×3（`LIST_X/LIST_Y`） | 右边 **5×5 灰色「?」方块阵**：x1112..1651 / y288..827，格距 108px |
| 翻页箭头 | 右侧「G」箭头中心 (1190,300) | 右侧**同样的箭头**，但位置是 (1857,540) → 基准 `SPECIAL_PAGE_RIGHT_POINT=(1238,360)` |

| 已通关的样子 | 金边缩略图 | 那一块显示**画作像素**（没有灰挡板了） |
| 未通关的样子 | 灰「?」卡片 | 灰「?」挡板（**光标停在上面的那块没有「?」字形，但仍是挡板**） |

代码里方阵是按 `SPECIAL_GRID_*`（1280×720 基准）记的，位置/格距都按窗口尺寸换算；
**「这一格打过没」用的是画面自己的颜色**：灰「?」挡板＝中性灰 150~216（实测 187）＝还没解开，
画作像素＝解开了。实测 25 格上：没解开 0.78 挡板占比 / 解开 0.00，分得很开。

**布局开关（三档）**：`--list-mode auto|normal|special`，也可以写进 `miku_bot_config.json`
的 `list_mode` 字段（默认 `auto`）。

- `auto`（默认）：按画面自己认——方块阵铺满那一整块（25 格里几乎没有黄底）就按特别谜题走，
  否则看浅黄卡片判据当普通谜题。**面板外壳（MikuPanel.exe）里烙死的参数白名单只认

  界面上的勾选项传不出新参数，所以自动识别是主路径；要强制指定就改配置或直接跑脚本。
- `normal` / `special`：只认其中一种。**另一种一律当「不是列表」**，宁可不动手也不乱点。

**怎么认出「这屏是特别谜题」**（`_list_kind`，两条都用画面自己当证据）：

1. **内部 8 条格线里明显的够多**，而且**最弱的那条也不能太弱**，并且**画面里检不出棋盘**。
   每条线的「明显程度」= 这条线上**逐点**亮度差绝对值的平均（`_special_line_values`）。
   ⚠ 两处都是坑，都在 2026-10-01 真机上踩过：
   - **不能「先平均再取绝对值」**：同一条线上既有画作格又有灰挡板格时，画作那段的差是负的、
     挡板那段是正的，先平均会互相抵消。真机实测解到 16 格时同一条横线「先平均」只剩 **4.0**，
     逐点绝对差是 **12.5** —— 于是判据不成立，症状是**「一排完了就不换行」**（扫不到下一格）
     加上**过关后认不出「已经回到方块阵」**（`advance_after_clear` 死点「继续」，面板日志连点 22 次）。
   - **光看格线分不开「关卡内棋盘填满」那一屏**：关卡内「关卡完成」时棋盘还在眼前，
     它自己的格线叠在这套坐标上，8 条线也全是明显的（最弱 10.2）。所以还要求
     「画面里**检不出棋盘**」（`auto_detect_candidates` 为空）。
   实测（逐点绝对差 + 候选数）：
   | 画面 | 明显条数 | 最弱那条 | 检出棋盘 |

   普通谜题列表 12 格、关卡内 0 格。
3. **要有灰挡板**（`SPECIAL_MIN_PLATES=1`，辅助判据）：一个都没有说明这一页基本打完了，
